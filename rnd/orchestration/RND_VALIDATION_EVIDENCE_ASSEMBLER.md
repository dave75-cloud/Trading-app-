# RND-0022 Governed Validation-Evidence Assembler

Status: R&D CANDIDATE / NON-OPERATIONAL
Automatic merge: NONE
Automatic promotion: NONE
Human merge decision: REQUIRED

## Purpose

RND-0022 bridges bounded machine evidence from RND-0021 and attested external
validation evidence into the unchanged candidate-evidence contract consumed by
RND-0020.

It assembles and verifies evidence. It does not execute tests or candidate code.

## Inputs

RND-0022 accepts explicit local artifacts:

- one RND-0020 work packet;
- one RND-0021 execution-evidence bundle;
- zero or more external validation attestations;
- one candidate changed-path manifest;
- one candidate output-hash manifest.

Every source artifact is bound to the same task ID, Git base, work-packet hash
and exact candidate repository HEAD.

## External validation attestation

An external record contains:

- version;
- task ID;
- Git base;
- exact tested HEAD;
- work-packet hash;
- validation label;
- PASS/FAIL;
- SHA-256 of the external evidence;
- producer identifier;
- content hash of the attestation itself.

The assembler validates these bindings and the attestation structure. It does
not independently prove that the external validation actually ran.

## RND-0021 evidence verification

The assembler verifies:

- the execution-evidence bundle hash;
- task/base/work-packet binding;
- exact repository HEAD;
- every action-evidence hash;
- exact equality between action evidence and validation rows;
- consistency of overall PASS/FAIL.

This prevents a validation row from being detached from the action evidence
that generated it.

## Validation-label policy

Only labels required by the work packet are accepted.

- duplicate labels: fail closed;
- unknown labels: fail closed;
- missing required labels: REVIEW_REQUIRED;
- failed validation: retained as FAIL.

RND-0022 never rewrites FAIL to PASS and never invents missing validation
evidence.

## Outputs

Two deterministic artifacts are produced.

### Candidate evidence

The candidate object remains exactly compatible with RND-0020:

- task ID;
- Git base;
- work-packet hash;
- changed paths;
- output paths and SHA-256 values;
- validation rows;
- fail-closed RND-0020 safety block.

### Assembly provenance

The sibling provenance artifact records:

- assembler version;
- exact candidate HEAD;
- candidate-evidence hash;
- all source-artifact hashes;
- validation-source mapping;
- required/present/missing labels;
- changed paths and output hashes;
- explicit trust boundary;
- human-only authority declarations;
- no-execution capability declarations;
- provenance content hash.

## Trust boundary

RND-0021 evidence is machine-generated by the bounded executor.

External validation evidence is attested input from a trusted external
runner/human-controlled process. RND-0022 verifies cryptographic and identity
bindings but does not re-execute or independently prove the external result.

## Safety

RND-0022 has no:

- subprocess capability;
- network capability;
- GitHub API capability;
- candidate-code execution;
- Git mutation;
- broker transport or submission;
- automatic disposition;
- automatic merge;
- automatic promotion;
- merge or promotion authority.

The assembler only reads explicit local JSON inputs and writes new output files
without overwrite.
