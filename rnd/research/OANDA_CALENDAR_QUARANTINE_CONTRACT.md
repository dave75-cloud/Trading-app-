# OANDA calendar-aware historical acquisition quarantine

Status: R&D CANDIDATE / READ-ONLY DATA ACQUISITION ONLY
Task: RND-0030
Base: `baa62608d734f0562470d6b4b1bc4eeeda4aa909`

## Purpose

RND-0030 is the first stage designed to obtain the real historical bytes needed
for the M005 reconstruction. It deliberately separates **acquisition** from
**performance-grade sealing**.

The standard session calendar is defined independently of returned candle data.
Returned data may expose discrepancies, but a missing returned candle cannot by
itself prove that the market was closed.

## Standard FX session

The baseline schedule uses the currently documented ordinary OANDA FX session
in New York local time:

- weekly open: Sunday 17:05;
- weekly close: Friday 16:59;
- daily break: 16:59 through 17:05;
- candle granularity: M5.

For M5 candle start timestamps, the baseline therefore includes 17:05 through
16:55 and excludes the 17:00 start. Saturday is closed. Sunday timestamps
before 17:05 and Friday timestamps after 16:55 are excluded.

The schedule is generated by converting each UTC M5 timestamp into
`America/New_York`; this makes DST an explicit timezone property rather than
a hand-coded UTC offset.

This baseline intentionally does **not** guess historical public-holiday
exceptions.

## Two-pass evidence model

### Pass 1 — quarantine acquisition

For each symbol and UTC calendar year:

1. generate the ordinary-session expected timestamp schedule;
2. fetch only the predeclared RND-0029 window through the existing Practice
   GET-only M5/MBA candle surface;
3. retain raw response pages and hashes;
4. retain canonical bid/ask/mid rows;
5. compute a standard-schedule digest;
6. produce an explicit missing/unexpected timestamp ledger;
7. write the shard to a new external quarantine directory.

A quarantine shard is evidence that bytes were acquired. It is **not** a claim
that the history is complete.

### Pass 2 — exception resolution

Any standard-session discrepancy remains unresolved until supported by
independent structural evidence. The permitted exception source class is an
official OANDA trading-hours/holiday notice whose identity and covered UTC
interval are recorded independently of the candle response.

The returned candle set cannot authorize deleting timestamps from the expected
calendar. Strategy signals, trades, returns or performance statistics can never
participate in exception classification.

## Year sharding

The ten-year horizon is divided into UTC calendar-year shards. This bounds
memory use and failure scope. Existing output is never overwritten. A later
resume mechanism may skip an existing shard only after verifying its recorded
evidence identity; otherwise it fails closed.

## Reserved final test

The 2023-01-01T09:40:00Z through 2025-01-01T00:00:00Z interval may be acquired
and structurally audited. It remains sealed against M005 signals, trade
simulation, performance metrics, parameter selection and strategy ranking.

## Credentials and authority

Practice token and account ID are runtime environment values only. They are
never committed, written to evidence or echoed in failure messages.

RND-0030 adds no order, trade, position, account-management, capital,
promotion, strategy-selection or merge authority.
